# 沙滩拾取规则编写指南

> 对应实现：`tools/ggz/ggz_daily.py` 顶部 `BEACH_RULES` + `BEACH_SAME_NAME_BEST`
> 规则引擎：字段 + 比较符 + 与/或/非/括号表达式，满足**任一**规则 → 拾取，全部不满足 → 清理

---

## 1. 规则总览

沙滩装备逐件决策，流程分两步：

```
① 规则判定（BEACH_RULES 逐条求值）
     ├─ 命中任一规则 → 进入 ②
     └─ 全部未命中 → 清理（日志显示"未命中规则"）
② 同名硬过滤（BEACH_SAME_NAME_BEST，默认开）
     ├─ 仓库+沙滩同批有更好同名 → 清理（日志显示"同名硬过滤"）
     └─ 相同或更好 → ✅ 拾取
```

## 2. 可用字段

规则只基于装备**自身信息**：

### 基础字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `name` | 字符串 | 装备名字（如 `探险者之剑`） |
| `mystery` | 布尔 | 是否含神秘词条 |
| `quality` | 数字 | 品质等级（3绿 / 4橙 / 5红…，icon 文件名末位） |
| `total_number` | 数字 | 词条总值%（= `affix0_pct + affix1_pct + affix2_pct + affix3_pct`） |

> **二级结论（2026-09-05）**：`total_number` 是派生字段，等于 4 个词条评分之和；它不是独立数据，只是方便整体比较的快捷字段。想筛选"某个词条怎么样"直接用 `affixN_*` 位置字段（见下节）。

### 词条位置字段（2026-09-05 新增）

装备固定 **4 词条**，且每种装备的词条**种类固定**（只有值不同）→ 可按位置访问单个词条：

| 字段 | 类型 | 含义 |
|------|------|------|
| `affix0` ~ `affix3` | 字符串 | 第 1~4 个词条文本（如 `生命偷取 +31.7%`） |
| `affix0_name` ~ `affix3_name` | 字符串 | 第 1~4 个词条名（如 `生命偷取`） |
| `affix0_pct` ~ `affix3_pct` | 数字 | 第 1~4 个词条评分（如 `129.0`） |
| `affix0_color` ~ `affix3_color` | 字符串 | 第 1~4 个词条颜色（`red` / `orange` / `blue` / `green` / `purple`） |

> ⚠️ 词条固定 4 个（实测），无"词条数量"字段；身上装备不参与判定（2026-09-05 用户指定）。
> ⚠️ 词条不足 4 个（解析异常/格式变化）时，对应位置字段比较结果为 **False**（不匹配，不报错）。

## 3. 比较符

### 数字字段（quality / total_number）

| 比较符 | 含义 |
|--------|------|
| `>=` `>` | 大于等于 / 大于 |
| `<=` `<` | 小于等于 / 小于 |
| `==` `!=` | 等于 / 不等于 |

### 字符串字段（name）

| 比较符 | 含义 | 示例 |
|--------|------|------|
| `==` `!=` | 精确匹配 | `name=='探险者之剑'` |
| `contains` | 包含子串 | `name contains '探险'` |
| `startswith` | 前缀匹配 | `name startswith '探险'` |
| `endswith` | 后缀匹配 | `name endswith '斗篷'` |

字符串值必须用引号包裹（单引号双引号均可）：`name=="探险者之剑"`、`name contains "探险"`

### 布尔字段（mystery）

直接写字段名即为"为真"，`not` 取反：

| 写法 | 含义 |
|------|------|
| `mystery` | 含神秘词条 |
| `not mystery` | 不含神秘词条 |

## 4. 表达式语法

### 逻辑运算符（按优先级从高到低）

| 运算符 | 含义 |
|--------|------|
| `( )` | 括号，改变优先级 |
| `not` | 非 |
| `and` | 与 |
| `or` | 或 |

### 示例

```python
"mystery and quality>=3"                    # 神秘 且 3等以上
"mystery or total_number>=516"                     # 神秘 或 总值≥516%
"not mystery and total_number>=410"                # 非神秘 且 总值≥410%
"quality>=3 and (total_number>=410 or mystery)"    # 括号优先：3等 且 (总值≥410 或 神秘)
"name contains '探险' and not mystery"      # 名字含"探险"（探险者之剑/布甲/皮甲…）且 非神秘
"affix0_name == '生命偷取'"                 # 第1个词条是生命偷取
"affix1_pct >= 130"                         # 第2个词条评分≥130%
"affix0_color == 'red' and affix1_color == 'orange'"  # 第1词条红+第2词条橙
```

## 5. 同名硬过滤（BEACH_SAME_NAME_BEST）

**默认开启**。命中规则的装备，若在**仓库 + 沙滩同批**中存在同名且更好 → 清理：

| 比较规则 | 结果 |
|----------|------|
| 品质更高（如 4橙 vs 3绿） | 品质高者收，低者清 |
| 同品质、总值更高 | 总值高者收，低者清 |
| 同品质、同总值（完全相同） | **都保留**（不互斥） |
| 无同名 | 不拦截，正常按规则 |

```python
BEACH_SAME_NAME_BEST = True   # 开启（默认）
BEACH_SAME_NAME_BEST = False  # 关闭（同名交给规则表达式自由决定）
```

## 6. 默认规则

```python
BEACH_RULES = [
    ("神秘",   "mystery"),
    ("可熔炼", "quality>=3 and total_number>=410"),
]
```

| 规则 | 表达式 | 说明 |
|------|--------|------|
| 神秘 | `mystery` | 含神秘必收（低品质神秘也收，神秘价值 >> 装备本身） |
| 可熔炼 | `quality>=3 and total_number>=410` | 供手动熔炼护身符（`smelt` 命令）；已涵盖橙装（总值≥516% 品质必≥3，且 smelt 有 `total_number<516` 兜底不误熔） |

> 其余一律清理（c=20 回收锻造石）。

## 7. 编写示例（自定义场景）

```python
# 例 1：只要神秘装，其余全清
BEACH_RULES = [
    ("神秘", "mystery"),
]

# 例 2：神秘 或 3等以上
BEACH_RULES = [
    ("神秘或3等", "mystery or quality>=3"),
]

# 例 3：只要指定装备的高值版本
BEACH_RULES = [
    ("探险者之剑高值", "name=='探险者之剑' and total_number>=450"),
]

# 例 4：只留神秘，且名字含"袍"的 3等以上
BEACH_RULES = [
    ("神秘袍3等", "mystery and name contains '袍' and quality>=3"),
]

# 例 5：按词条筛选——第1词条是生命偷取且评分≥120 的高值装
BEACH_RULES = [
    ("生命偷取高值", "affix0_name == '生命偷取' and affix0_pct >= 120 and quality >= 3"),
]

# 例 6：词条组合——第2词条是附加物伤且第3词条评分≥100
BEACH_RULES = [
    ("物伤高值", "affix1_name contains '物伤' and affix2_pct >= 100"),
]
```

## 8. 验证方法

运行沙滩命令后，日志会**逐件打印决策及原因**，直接验证规则是否生效：

```
沙滩 10 件，身上 3 件，仓库 5 件
逐件决策（规则引擎）:
  ✅ 复苏战衣 4等 466% → 拾取 [神秘]
  ✅ 幽梦匕首 3等 465% → 拾取 [可熔炼]
  ➖ 彩金长剑 3等 430% → 清理（同名硬过滤（存在更好的同名, 即使命中规则也不收））
  ➖ 探险者布甲 1等 200% → 清理（未命中规则）
决策: 拾取 2 件, 清理 2 件
```

- ✅ = 拾取，方括号内为**命中规则名**
- ➖ = 清理：`（同名硬过滤...）` = 命中规则但同名有更好；`（未命中规则）` = 本身不满足任何规则

## 9. 容错与注意事项

- **规则写错不崩**：单条规则解析/求值失败 → 日志告警并跳过该条，其他规则继续
- **未知字段报错**：提示可用字段列表（`mystery, name, quality, total_number`）
- **名字解析失败**（显示 `?`）→ 同名硬过滤直接放行（不因解析失败误清）
- **仓库读取失败（限流）** → 同名硬过滤退化为仅对比沙滩同批（保守偏向收）
- **满足任一规则即收**：规则间是"或"关系，命中靠前的规则后序不再判断
- **改完规则直接生效**：无需命令行参数，改 `BEACH_RULES` 后重跑 `beach` 即可
