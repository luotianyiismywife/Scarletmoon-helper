# 文档与代码一致性规则

> 本文件是仓库级规则，Copilot 在编辑本仓库代码时必须遵守。

## 核心原则

**修改任何 JS 文件后，必须同步检查并更新对应的 MD 文档**，保证文档描述与代码实际行为一致。不允许出现"文档说 X，代码做 Y"的情况。

## 文件对应关系

| JS 文件 | 对应文档 | 同步内容 |
|---------|---------|---------|
| `src/main.js` | `src/main.md` | 元数据、模块加载机制、菜单命令、执行流程 |
| `src/sign-module.js` | `src/sign-module.md` | API 列表、参数/返回值、常量、内部辅助函数、解析规则 |
| `build.js` | `build.md` | 构建步骤、内联标记约定、产物说明 |
| 任一变更 | `README.md` | 安装方式、签到说明、脚本说明、文档索引 |
| 规则本身 | `.copilot/instructions.md` | 涉及文件对应关系、检查清单、业务约定的变更需同步本文件 |

## 修改 JS 后的必查清单

1. **API 变更**（`src/sign-module.js`）：
   - 新增/删除/重命名导出 → 更新 `sign-module.md` 功能说明章节编号与内容
   - 参数或返回值结构变化 → 更新对应章节的字段列表
   - 新增内部函数 → 更新"内部辅助函数"章节
   - 常量变化（`DENY_TEXT`、`TARGET_TEXT`、正则等）→ 更新"核心常量"章节

2. **主脚本变更**（`src/main.js`）：
   - 元数据（`@grant`、`@match`、`@version` 等）变化 → 更新 `main.md` 元数据表
   - 模块加载逻辑变化 → 更新"模块加载机制"章节
   - 菜单命令变化 → 更新"菜单命令"表

3. **构建变更**（`build.js`）：
   - 转换规则、产物路径、标记约定变化 → 更新 `build.md`

4. **所有变更**：
   - 检查 `README.md` 的"签到说明"和"脚本说明"是否过时
   - 若 JS 版本号更新（`@version`），同步更新 `README.md` 中引用的版本

5. **规则变更**（本文件）：
   - 若文件对应关系、检查清单、业务约定发生变化，必须先更新本文件再执行变更

## 禁止事项

- ❌ 修改 JS 后跳过 MD 更新
- ❌ 在 MD 中描述代码不存在的功能（如不存在的开关、不存在的 API）
- ❌ 文档中保留过时的链接模式/文本判定描述（如把 `ok=2&color=N` 描述为签到链接）
- ❌ 章节编号断档或重复

## 特殊约定（绯月论坛签到业务知识）

- 论坛页面为 **GBK 编码**，必须经 `decodeResponse` 解码，文档中不得描述"直接 `response.text()`"
- `kf_growup.php?ok=2&safeid=...&color=N` 是 **ID 颜色设置链接，不是签到**，文档中必须注明"需排除"
- 签到动作预计为 `kf_growup.php?ok=1&safeid=...`（未验证前文档需保留"待验证"标注）
- `getDefaultSignModule()` 返回对象不包含 `parseSignStatus`，文档需保持一致

## 构建后检查

运行 `node build.js` 后，确认：
- 产物路径为 `dist/allinone.user.js`
- 若构建脚本行为变化，`build.md` 需同步

## 更新流程示例

修改 `src/sign-module.js` 的正确流程：

1. 修改代码
2. 检查 `src/sign-module.md` 对应章节并更新
3. 检查 `README.md` 相关描述
4. `node build.js` 重新构建产物
5. 提交时同时包含代码与文档变更
