- 21 项属性：生命/物攻/魔攻/绝攻/攻速/物穿/魔穿/技能率/暴击/暴击穿透/吸血/物防/魔防/物减伤/魔减伤/护盾/护盾回复/反弹/暴击抵抗/技能抵抗 + 六维
- 装备格式：`武器名 基础值×5 + 数字`；护符：`品质水果(+等级)=属性 数值`
- **武器位编码**（战报/分享串）：`BLADE 100 92 110 105 130 1 / CLAYMORE ×2 / DAGGER / BOW ×2 / RING / CAPE / THORN / LEATHER / FIERCE / SCARF`（每段 = 装备类型 + 基础值×5 + 数字）
- **护符编码**：`001-012`（如 `史诗蓝银葡萄(+3)=PATK 3`、`稀有星铜苹果(+1)=STR 3`）——序号=品质+名称映射，可对照 03 装备类型表
- **胜率记录格式**：`SHI Lv.200 : Win Rate : 85.59% (1675/1957 D=43)`（角色拼音 等级 : 胜率 (胜/负 D=平局)）

### 3.3 装备属性格式
- `生命偷取 +31.7% 129%`（基础值 + 百分比加成）
- `附加物防 +386.7 132%`
- `[神秘属性]xxx`（如"削弱对方40%回血回盾"）
- 装备数值公式：**装备等级 × 词条百分比**（简单乘算）
- 橙装 = 词条总值 516%-585% 之间

### 3.4 PVP 匹配消息文本（脚本判断用）
- `随机对手近日无胜场，不计出击次数，请重试`（轮空，不计次数，可循环重打）
- `随机匹配轮空或对手段位改变，请重新点击攻击其他玩家。本次不消耗体力。`
- 段位低/人少时 PVP 容易轮空死循环
- **打野、打人（非轮空）都计入出击次数**（2026-08-06 实测：打人失败后 0/1→0/2）

### 3.5 战斗记录 `f=25`（脚本检测被攻击用，2026-08-06 实测）
- **只记录 PVP（打人/被打）**，打野不产生记录
- 返回 HTML 每行一条：`今天 X时 | 攻/被攻 | 胜/败 | [对手]名 | Lv.X 职业 | 空`
- 用途：检测**是否被其他玩家攻击**（防御全败不掉进度 → 可只打进攻不管防守，但被攻击记录可统计）
- 页面加载自动调用（`pklog()`），无需手动点击

## 4. 自动化决策规则（写智能逻辑用）

### 4.1 日常 2 分钟流程（可脚本化）
1. **宝石工坊**：开工→领取→开工（每日收益）
2. **道具工坊**：日限 10w 贝壳
3. **我的沙滩**：清理沙滩，黄红装备留着（可拆成饰品）
4. **争夺战场**：攻击玩家点满 20 次出击
5. **翻牌子**（最左个人信息）：3 张相同颜色牌出奖励

### 4.2 出击策略
- **出击时间**：早上 8 点前出击胜率高（多帖印证）；"S 大段走位大于努力"
- **打人收益 > 打野**：打人即便失败也有幻影经验/成长（2026-08-06 实测：失败不掉狗牌、进度 -3%，仍计出击）
- **⭐ 优先打人策略（2026-08-16 用户指定 + 坛友 zerostar 建议）**：脚本 `pk()` 默认**先打人（id=2）**——胜利 +3% 进度（打野仅 +1%）、失败也 +1 出击；打人失败/轮空/平局 → 切打野（id=1，CC 段打野稳赢）；打野失败 → 停止
  - **CC 段打人实测（08-16）**：连续 3 次全轮空（"随机对手近日无胜场，不计出击次数"）——低段位玩家少，匹配不到对手，**轮空零损失**
  - 打人轮空/打野稳赢的组合在低段位最有效：先试打人（可能 +3%），轮空立刻切打野（+1% 保底）
- **100 回合平局不计次数**；A 段以下掉段自动给 1 狗牌
- **防守全败不掉进度** → 脚本可只打进攻不管防守
- 出击次数逻辑：PVP 胜利/失败都 ±3% 进度（2025-01 后）；升段 +10% 进度、掉段 →90%
- **打野突破（2026-08-10 实测结论）⭐**：
  - 野怪固定"绝底线"减伤：物/法伤 -90%、绝伤 -88%、反伤 -50%（fyg_pk.php 说明）
  - **纯物/法输出打野被砍 90%**（实测 53244 总输出仅 3564 有效盾损）→ **打野必须靠绝对伤害**（削骨之痛天赋/神秘装绝伤）
  - 史莱姆"反伤!"+高回盾 → 天赋优先**精神创伤302（-70%回盾）+ 伤口恶化301（-70%回血）+ 削骨之痛205（1.5%最大生命绝对伤害）**
  - **加点暴涨优先级最高**（生命 1447→67621、物攻→15590），先加点再打野
  - 卡段死循环（C↔CC↔CCC 横跳）根源 = 装备品质不足 + 没加点 + 无绝伤 → 三者补齐后突破

### 4.3 翻牌与狗牌
- 翻牌需 **3 张狗牌**（曾临时取消）；PVP 和 PVE 胜利都得 1 狗牌
- 翻牌方式：从左依次向右翻，3 张相同颜色出奖励

### 4.4 打野机制
- **野怪动态等级**：受玩家涌入/降级影响（BB 段史莱姆 150-170，BBB 230-300）
- **不同角色对应不同野怪**，强度不同（舞/梦/希差异大）
- 平局不计次数（可利用：稳赢/平局打法稳定上分）
- 打野角色排行：T0 梦/希，T1 雅/薇，下水道冥

### 4.4b 加点规则（角色六维，2026-08-10 实测）⭐

> 入口：`fyg_equip.php` → 角色卡片 tab → 点角色卡 → `f=18&zid=<角色id>`

**总属性点来源：**
```
总属性点 = (6 + 角色等级×3) × (1 + 品质%)     ← 2026-08-10 实测推导
例：舞 Lv.800 品质8% → 2406 × 1.08 = 2598
```

#### 产出机制（实测确认）

工坊 6 栏分两类：

| 类型 | 栏 | 增长方式 | 上限 |
|------|-----|---------|------|
| **概率型** | 随机装备箱 / 灵魂药水 / 宝石原石 | 概率线性涨（%），**100% 封顶** | 收工结算 **1 件**，不会产 2-3 件 |
| **累积型** | 贝壳 / 星沙 / 幻影经验 | 数值直接累积 | 星沙 10 粒；贝壳约 91 万 |

**关键：概率栏 100% 封顶 = 单件产出**（2026-08-14 实测 + slack 源码印证）。开工再久，每栏收工最多 1 件。

#### 增长率公式（论坛潭友 alexvoid42 验证，tid=982612）⭐⭐

> **⚠️ 卡片等级系数用的是「工坊显示等级」，不是卡片装备页等级**（2026-08-14 实测：卡片全 801，工坊里默 190/琳 186/命 800 等，工坊等级是独立快照，见 01 §1.1）。等级系数查下表用工坊 f=21 显示等级。

**6 栏公式**（单位：贝壳/分、概率万分比/分、星沙万分比/分、幻影千分比/分）：

| 栏 | 公式 |
|----|------|
| 贝壳 | `20 + 10×卡系 + 5×红石数` |
| 随机装备箱 | `0.0001% × (200 + 20×卡系 + 10×银石数)` |
| 灵魂药水 | `0.0001% × (150 + 15×卡系 + 10×金石数)` |
| 宝石原石 | `0.0001% × (150 + 15×卡系 + 10×梦石数)`（同灵魂药水） |
| 星沙 | `0.0001 × (7 + 1×卡系 + 1×虚石数)` |
| 幻影经验 | `0.001 × (20 + 3×卡系 + 3×幻石数)` |

**✅ 我们实测验证（2026-08-14）**：
- 梦石1、琳186（卡系1）→ 原石 `0.0001%×(150+15×1+10×1)=0.0175%` ✓ 与面板一致
- 红石3、默190（卡系1）→ 贝壳 `20+10×1+5×3=45` ✓ 与面板 +45/分 一致
- 虚石0、希800（卡系12）→ 星沙 `0.0001×(7+12+0)=0.0019` ✓ 与面板一致

**⚠️ 注意**：此公式为 2023 年验证，**当前版本可能有微调**；"面板显示增长率 vs 实际增速"若有偏差（我们观察过装备箱栏面板0.045 vs 实测0.034），可能是公式常数/卡系段位改过，欢迎后续再验证。

**满宝石+850卡最大产出**：贝壳+440/分、装备箱+0.104%/分、原石+0.0705%/分、星沙+0.0034/分、幻影+0.101/分。

#### 旧帖玩家共识（tid=996593「多久收一次划算」+ 979005「概率问题和宝石获取」）⭐

- **24h 收一次**是主流（多人提到"我都是 24 小时收一次"）；运气好 3 道具、差 2 道具

- 有玩家 107h 收一次（等星沙满），有玩家概率 80%+ 才收（不信运气）
- **数学结论（springfestiv 推导，坛友互相纠正后）**：
  - 某段时间概率线性到 p，若收 n 次：期望收益 **μ = p（与 n 无关）** → **收快收慢期望一样**

### 4.5 沙滩装备收取/清理规则 ⭐可配置
> 依据：装备数值公式 = 等级×词条%，橙装=词条总值516-585%，分解出+5看等级（250以下无价值）
> **已实测验证**（2026-08-05）：收取/穿戴/清理全流程跑通

**沙滩装备数据格式（实测 `f=1` 返回，2026-08-23 更新新格式）**：每件 = 等级 + 名称 + 星级(`icon-star` 数) + 词条列表（名称+数值+百分比，颜色分级 danger红/warning黄/info蓝/success绿/primary）

**⚠️ 新版按钮结构（2026-08-23 实测）**：`title` 为空、名字在 `data-original-title`（`Lv.<span class='fyg_f18'>100</span> ...<br>装备名`）；词条在 `data-content`。**两种转义**：f=1 接口返回**未转义**原生 HTML，`fyg_beach.php` 页面 DOM 是**转义版**（`&lt;p class=...&gt;`）→ 解析前统一 `html.unescape()`。接口/格式细节见 [02-接口.md](02-接口.md) §3.1/[04-规则细节.md](04-规则细节.md) §4.4。

**✅ 词条明细解析（2026-08-23 新增，装备记录用）**：`parse_equips()` 返回每件装备 `affixes` 数组 `[{name, text, pct, color}]`：
- `text` = 完整词条文本（如 `物理攻击 +64.4%` / `附加魔穿 +146`），取自 `<p>` 内 `<span` 前部分
- `pct` = 词条**评分百分比**（`pull-right bg-XXX` 里的 N%），`color` = 裸 class 名（`info/success/primary/danger/warning`）
- 日志输出：`beach()` 逐件打印完整属性（名称/品质/总值/icon/id/词条标记 + 每个词条文本+评分+颜色中文），供装备记录复制
- 词条颜色中文映射：`danger=红 / warning=橙 / info=蓝 / primary=紫 / success=绿`

**⚠️ DOM 解析关键（2026-08-11 实测教训）**：每个装备按钮 `onclick="zbtip('ID','4')"` 中的 **ID 属于该按钮**，而 icon（`zXXXX_N.gif`）与名字位于**同一按钮内、onclick 之前**。若按 `split("zbtip('")` 的"块首 id"解析会**整体错位一位**（拾取错装备）。正确配对正则：
```js
/z(\d{4})_(\d)\.gif[^]*?(?:title|data-original-title)="Lv\.[^"]*?([^"]*?)"[^]*?zbtip\('(\d+)','4'\)/g
//  类型码    品质             名称（新旧格式兼容）          id（同一按钮内）
```
> ⚠️ 新格式（2026-08-23）`title` 为空、名字在 `data-original-title`，正则需 `(?:title|data-original-title)` 兼容两种；解析前先 `html.unescape`（页面 DOM 转义版）。
词条百分比 = `data-content` 中 `<span class='pull-right bg-*'>&nbsp;N%&nbsp;</span>` 的 N（注意正则 `(?:\.\d+)?` 的 `?` 不能漏，否则小数格式失配）。

**⚠️ 沙滩 id 重排（2026-08-11 实测）**：拾取一件后**剩余沙滩装备 id 全部重排**，且仓库↔沙滩移动也会变 id → **每步操作后重新读 f=1/f=2**，禁止复用旧 id（与护身符/穿脱 id 变化同源）。

**⭐ 拾取规则引擎（2026-09-05 重构，可配置）**：`ggz_daily.py` 顶部 `BEACH_RULES` 为**用户自定义规则列表**，每条 = (名称, 表达式)。表达式 = **装备字段 + 比较符 + 值**，用 `and` / `or` / `not` / 括号（支持优先级）组装。满足**任一**规则 → 拾取；全部不满足 → 清理。无需命令行参数，改配置即改规则。

**可用字段**（作用于沙滩装备，上下文 = 仓库+身上+沙滩同批）：

| 字段 | 类型 | 含义 |
|------|------|------|
| `name` | 字符串 | 装备名字，可 `==` `!=` `contains` `startswith` `endswith`（值用引号） |
| `mystery` | 布尔 | 是否含神秘词条（直接 `mystery` / `not mystery`） |
| `quality` | 数字 | 品质等级（3绿/4橙/5红…），可 `>= > <= < == !=` |
| `total` | 数字 | 词条总值%（几个词条百分比之和） |
| `orange` | 布尔 | 是否橙装（total≥516） |
| `red_orange` | 布尔 | 是否含红/橙词条 |
| `high_affix` | 布尔 | 是否含高价值词条（生命偷取/附加物伤/附加魔伤/附加物穿/附加魔穿/技能概率/暴击概率/攻击速度） |
| `empty_slot` | 布尔 | 身上该部位是否空缺 |
| `beat_worn` | 布尔 | 词条总值是否高于身上同部位任何一件 |
| `same_name_best` | 三值 | 同名装备保留最好（有同名→最好收/次品清；无同名→中性，交给其他规则） |

**比较符**：数字字段 = `>= > <= < == !=`；名字字段 = `== != contains startswith endswith`（字符串值用引号，如 `name=='探险者之剑'`、`name contains '之剑'`）。

**⭐ 同名硬性过滤（2026-09-05 新增，默认开）**：`BEACH_SAME_NAME_BEST = True` 时，沙滩装备存在同名（仓库+身上+沙滩同批）且**不是其中品质最高**（品质数字 3绿/4橙/5红；同品质比总值）→ **直接清理，不进入规则判定**——即"同名装备只在仓库保留最好的"。设 False 则完全交给表达式决定。

**示例（用户自定义）：**
```python
BEACH_RULES = [
    ("保留最好或神秘3等", "same_name_best or (mystery and quality>=3)"),
    ("指定名高值",        "name=='探险者之剑' and total>=450"),
    ("名字含剑且非神秘",   "name contains '剑' and not mystery"),
]
```

**默认规则（= 原 4.5 全部行为 + 同名去重）：**
```
橙装 / 神秘 → 无脑收
可熔炼（quality>=3 and total>=410）→ 收（供手动熔炼）
红橙词条 含高价值 → total>=450 / 无高价值 → total>=500
优于身上（empty_slot or beat_worn）→ 收
同名最好（BEACH_SAME_NAME_BEST 硬过滤前置）→ 收
其余 → 清（c=20 回收锻造石）
```

> 原静态规则对照（2026-08-13 更新）：① 橙装≥516% 无脑收 ② 神秘必收 ③ 品质≥3且总值≥410% 收（熔炼线）④ 红/橙词条高价值→450%、无→500% ⑤ 优于身上同部位/空部位收 ⑥ 其余清。全部已映射为默认 BEACH_RULES。

**✅ f=1 读取铁律（2026-09-03 定稿，作废"空窗期"一词）：先 GET 后 POST，别密集轮询。**

f=1 返回空**不存在任何服务器"空窗期"**，历史上先后被误记为 64s / 90s / 15-21s 空窗，全部是以下两类**可复现原因**的误测：

  - **原因 a：缺 reload（主因，已根治）**。浏览器 `gx_sxst()` 在 c=12 返回 ok 后执行 `window.location.reload()`（整页 GET `fyg_beach.php`），页面加载时 `stall()` 再 POST f=1。**接口和脚本完全一样**（c=12 + f=1），唯一差异就是浏览器多了这次整页 GET——服务端需要一次页面 GET 确认状态，脚本冷 POST f=1 就返回空。
  - **原因 b：真限流（独立机制）**。高频轮询 f=1（间隔 <5s）触发 f=1 专属限流：f=6/2/12 正常但 f=1 连浏览器同 IP 都空（08-23 实测）。返回空与"真空"同形，`_read_beach` 的 f=6 探测用于区分。

**证据时间线（08-24，同接口同 IP 同时刻，唯一变量是 reload）：**

| 时间 | 行为 | 结果 |
|---|---|---|
| 08-18~08-23 | 脚本从未 GET 过 `fyg_beach.php`，直接 POST f=1 | 多次"0 字符疑似限流"误判事故 |
| 08-24 10:09 | c=12 后直接 POST f=1（无 GET） | 55s 内 4 次读取全空 |

**当前实现（`beach()`）= GET-first + 低频兜底：**
  1. c=12 后**先 GET `fyg_beach.php`**（模拟 reload）→ 立即读 f=1（**不等待**，治原因 a）；
  2. 仍空则 10s 间隔重试，最多 4 次（防原因 b/服务器延迟，勿改 2s 密集轮询）；
  3. **普适规律**：任何场景读 f=1 前若从未 GET 过 `fyg_beach.php` 都可能空——

     单独调 `_read_beach` 的场景需自行保证先 GET。
  4. 重试兜底是保险，不是主策略：GET-first 生效后正常路径第 1 次即成功，
     待样本进一步积累可考虑精简。

**⚠️ Python urllib 限流问题（2026-08-16 确认 → ✅ 已迁移 requests.Session）**：
- **现象**：momozhen 对 Python urllib 连续请求限流严重——SSL 频繁断开（`UNEXPECTED_EOF_WHILE_READING`）、响应返回空（0 字节）、偶发 HTTP 错误；**浏览器 fetch 稳定不受影响**
- **根源**：urllib 每次 `urlopen` 都新建 TCP 连接 + TLS 握手，无连接池无 keep-alive，高频请求易触发服务器限流/DDoS 防护；且 `Content-Length`/头顺序等细节与真实浏览器有差异
- **✅ 已迁移（2026-08-16 深夜）**：`ggz_daily.py` 的 `request()` 改用 **requests.Session**（连接池 + keep-alive 复用 + 指数退避重试 `2^n + jitter`）。迁移后 stat/beach/gem 全流程**零重试**（旧 urllib 版 stat 都常 SSL 断开重试 1-2 次）。`requests` 依赖需 `pip install requests`（2.34.2 实测）
- **剩余规避手段（如需进一步优化）**：
  1. **降低请求频率**：批量操作（如 beach 逐件拾取、c=27 宝石连提）分批发、每发间隔 ≥2s（记忆 08-13 深夜：c=27 连发第 4 个起超时失败）
  2. **浏览器兜底**：脚本频繁失败时改用浏览器 MCP 操作（fyg 接口 fetch 直调），日常大数据量操作优先浏览器

**⚠️ f=1 读取失败 ≠ 沙滩空（2026-08-18 踩坑修复，重要）**：
- **现象**：`all_daily` 跑到沙滩时，其他步骤（加点/工坊/宝石/许愿）全部正常，唯独沙滩判定"空，无装备"跳过。实际浏览器打开有 10 件装备
- **根源**：旧代码 `read_block(1)` 返回空/异常时（限流返回空 body、会话失效返回"请重新登录"），`parse_equips` 解析出 0 件 → 直接走"沙滩空"分支，**不区分"读取失败"和"真空"**
- **会话互顶**：咕咕镇 cookie 单会话 + 每日刷新。用户在浏览器打开游戏页 → 服务器发新会话 → 旧 cookie 立即失效 → 脚本所有请求返回"请重新登录"（9 字符）。但如果脚本先跑、浏览器后开，则脚本期间 cookie 有效
- **⚠️ cookie.txt 快照陷阱（2026-08-23 补）**：`cookie.txt` 不会自动同步浏览器会话。浏览器导航入口链后服务器下发新 `gamepw`，cookie.txt 仍是旧值 → 脚本 `fyg_read.php` 全 27 字节"请重新登录并刷新！"（`fyg_index.php` 可能仍正常）→ 曾被误判"限流"。解决：跑日常前若浏览器开过游戏页，先 `--refreshggz` 或从浏览器同步会话（机制见 [02-接口.md](02-接口.md) §1.2）
- **✅ 修复（2026-08-18）**：新增 `_read_beach()` 函数，带重试验证：
  1. 返回含"请重新登录" → 直接 raise 提示重抓 cookie（不重试，无意义）
  2. 返回 <20 字符 → 疑似限流空响应，等待后重试（最多 3 次）
  3. 含 `<button` + `ys/icon/z` 但 parse_equips 解析 0 件 → HTML 格式变化，重试
  4. 正常 HTML 无装备按钮 → 确认真空
- **✅ 二次修复（2026-08-23，空沙滩 vs 限流）**：f=1 空沙滩**本身就返回空字符串**（02 §3.1），与限流 0 字节同形，`<20 字符` 判定会误判真空为限流（08-21 日志 beach 全失败即此因）。改为 **f=6 探测**：f=1 短时同时 POST f=6（身上装备）——**f=6 正常 = 沙滩真空**（返回 `[], raw` 走真空分支）；f=6 也空才是真限流（等待重试）
- **教训**：任何"读取→解析→判空"的流程，都必须区分"读取失败"和"数据为空"，不能把异常静默当空处理
