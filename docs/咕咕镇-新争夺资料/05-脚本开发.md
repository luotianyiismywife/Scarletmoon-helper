- `生命偷取 +31.7% 129%`（基础值 + 百分比加成）
- `附加物防 +386.7 132%`
- `[神秘属性]xxx`（如"削弱对方40%回血回盾"）
- 装备数值公式：**装备等级 × 词条百分比**（简单乘算）
- 橙装 = 词条总值 516%-585% 之间

### 3.4 PVP 匹配消息文本（脚本判断用）
- `随机对手近日无胜场，不计出击次数，请重试`（轮空，不计次数，可循环重打）
- `随机匹配轮空或对手段位改变，请重新点击攻击其他玩家。本次不消耗体力。`
- 段位低/人少时 PVP 容易轮空死循环
- **打野、打人（非轮空）都计入出击次数**（2026-08-06 实测：打人失败后 0/1→0/2）

### 3.5 战斗记录 `f=25`（脚本检测被攻击用，2026-08-06 实测）
- **只记录 PVP（打人/被打）**，打野不产生记录
- 返回 HTML 每行一条：`今天 X时 | 攻/被攻 | 胜/败 | [对手]名 | Lv.X 职业 | 空`
- 用途：检测**是否被其他玩家攻击**（防御全败不掉进度 → 可只打进攻不管防守，但被攻击记录可统计）
- 页面加载自动调用（`pklog()`），无需手动点击

## 4. 自动化决策规则（写智能逻辑用）

### 4.1 日常 2 分钟流程（可脚本化）
1. **宝石工坊**：开工→领取→开工（每日收益）
2. **道具工坊**：日限 10w 贝壳
3. **我的沙滩**：清理沙滩，黄红装备留着（可拆成饰品）
4. **争夺战场**：攻击玩家点满 20 次出击
5. **翻牌子**（最左个人信息）：3 张相同颜色牌出奖励

### 4.2 出击策略
- **出击时间**：早上 8 点前出击胜率高（多帖印证）；"S 大段走位大于努力"
- **打人收益 > 打野**：打人即便失败也有幻影经验/成长（2026-08-06 实测：失败不掉狗牌、进度 -3%，仍计出击）
- **100 回合平局不计次数**；A 段以下掉段自动给 1 狗牌
- **防守全败不掉进度** → 脚本可只打进攻不管防守
- 出击次数逻辑：PVP 胜利/失败都 ±3% 进度（2025-01 后）；升段 +10% 进度、掉段 →90%
- **打野突破（2026-08-10 实测结论）⭐**：
  - 野怪固定"绝底线"减伤：物/法伤 -90%、绝伤 -88%、反伤 -50%（fyg_pk.php 说明）
  - **纯物/法输出打野被砍 90%**（实测 53244 总输出仅 3564 有效盾损）→ **打野必须靠绝对伤害**（削骨之痛天赋/神秘装绝伤）
  - 史莱姆"反伤!"+高回盾 → 天赋优先**精神创伤302（-70%回盾）+ 伤口恶化301（-70%回血）+ 削骨之痛205（1.5%最大生命绝对伤害）**
  - **加点暴涨优先级最高**（生命 1447→67621、物攻→15590），先加点再打野
  - 卡段死循环（C↔CC↔CCC 横跳）根源 = 装备品质不足 + 没加点 + 无绝伤 → 三者补齐后突破

### 4.3 翻牌与狗牌
- 翻牌需 **3 张狗牌**（曾临时取消）；PVP 和 PVE 胜利都得 1 狗牌
- 翻牌方式：从左依次向右翻，3 张相同颜色出奖励

### 4.4 打野机制
- **野怪动态等级**：受玩家涌入/降级影响（BB 段史莱姆 150-170，BBB 230-300）
- **不同角色对应不同野怪**，强度不同（舞/梦/希差异大）
- 平局不计次数（可利用：稳赢/平局打法稳定上分）
- 打野角色排行：T0 梦/希，T1 雅/薇，下水道冥

### 4.4b 加点规则（角色六维，2026-08-10 实测）⭐

> 入口：`fyg_equip.php` → 角色卡片 tab → 点角色卡 → `f=18&zid=<角色id>`
> 实测：账号 <用户名> 的"舞"原本完全没加点（六维 20/20/20/10/10/10 = 已分配 90，总 2598 点没动）→ **2026-08-10 已全加完**（力量1559/体魄470/意志519），生命 1447→67621、物攻→15590，属性暴涨

**总属性点来源：**

### 4.5 沙滩装备收取/清理规则 ⭐可配置
> 依据：装备数值公式 = 等级×词条%，橙装=词条总值516-585%，分解出+5看等级（250以下无价值）
> **已实测验证**（2026-08-05）：收取/穿戴/清理全流程跑通

**沙滩装备数据格式（实测 `f=1` 返回）**：每件 = 等级 + 名称 + 星级(`icon-star` 数) + 词条列表（名称+数值+百分比，颜色分级 danger红/warning黄/info蓝/success绿/primary）

**⚠️ DOM 解析关键（2026-08-11 实测教训）**：每个装备按钮 `onclick="zbtip('ID','4')"` 中的 **ID 属于该按钮**，而 icon（`zXXXX_N.gif`）与 title（`Lv.X 星级 名称`）位于**同一按钮内、onclick 之前**。若按 `split("zbtip('")` 的"块首 id"解析会**整体错位一位**（拾取错装备）。正确配对正则：
```js
/z(\d{4})_(\d)\.gif[^]*?title="Lv\.[^"]*?([^"]*?)"[^]*?zbtip\('(\d+)','4'\)/g
//  类型码    品质             名称                    id（同一按钮内）
```
词条百分比 = `data-content` 中 `<span class='pull-right bg-*'>&nbsp;N%&nbsp;</span>` 的 N（注意正则 `(?:\.\d+)?` 的 `?` 不能漏，否则小数格式失配）。

**⚠️ 沙滩 id 重排（2026-08-11 实测）**：拾取一件后**剩余沙滩装备 id 全部重排**，且仓库↔沙滩移动也会变 id → **每步操作后重新读 f=1/f=2**，禁止复用旧 id（与护身符/穿脱 id 变化同源）。

**核心规则：原 4.5 规则 + 红/橙词条≥430% 无脑收（2026-08-13 更新）** ⭐
```
收取条件（并集，满足任一即收）：
  ① 橙装（总值≥516%）→ 无脑收（备其他角色）
  ② 含神秘 → 必收
  ③ 能熔炼（品质≥3 且总值≥410% 且无神秘 且非橙装）→ 收（供手动熔炼，长期规则）
  ④ 红词条(bg-danger) 或 橙词条(bg-warning)：
     含高价值词条 → 四词条总数≥450% 无脑收
     无高价值词条 → 四词条总数≥500% 无脑收
  ⑤ 同部位对比：沙滩总值 > 身上同部位 → 收；无同部位（空部位）→ 收
  ⑥ 其余 → 清（c=20 回收锻造石）
```

**收取判断表（按优先级）：**

| 优先级 | 场景 | 收取 | 清理 |
|--------|------|------|------|
| 🥇 | **橙装**（词条总值 ≥516%） | ✅ **无脑收**（备其他角色） | - |
| 🥈 | 含神秘词条 / 星级≥2 | ✅ 必收 | - |
| 🥉 | 能熔炼（品质≥3 且总值≥410% 且无神秘 且非橙装）→ 收（供手动熔炼） | ✅ 收 | - |
| 4 | **红/橙词条 含高价值 → ≥450%** / **红/橙词条 无高价值 → ≥500%**（新增） | ✅ **无脑收** | - |
| 5 | 沙滩装评分 > 身上同部位 | ✅ 收 + 可选替换 | - |
| 6 | 空部位（未穿戴） | ✅ 收 | - |
| 7 | 其余（沙滩装评分 ≤ 身上同部位 / 低值） | - | 清 |

> ⚠️ **橙装判定**：词条总值 = 各词条百分比之和，516-585% 为橙装（知识点确认）。沙滩装备 `data-content` 里每个词条带百分比，直接求和判断。
> ⚠️ **熔炼线**：词条总值 ≥410% **且品质 ≥稀有** 可熔炼为护身符（2026-08-06 实测 406%不可熔/425%可熔；2026-08-10 实测 418% 普通品质不可熔，返回"至少需要稀有级别的装备才可以熔炼"）；护身符在"我的饰品"栏即生效，不占装备槽。
> ⚠️ **同部位对比部位码（2026-08-16 实测修复，重要）**：沙滩/身上装备 icon 是 **4 位数字**（如 `2101`/`2111`），部位类 = **前 2 位数字**（21武器/22手环/23衣服/24饰品）。⚠️ 旧代码 `icon[:3]` 把武器内部子类当不同部位（`2111[:3]`=`"211"` vs `2101[:3]`=`"210"`），导致沙滩 211x 武器 vs 身上 210x 武器被判"空部位"→ **白板/蓝装武器全被收仓**。已修复为 `icon[:2]`（2026-08-16 当日 10 件沙滩数据验证：修复后仅神秘装被收）。

**词条价值判断（针对角色构筑）：**
- **高价值词条**：生命偷取/附加物伤/附加魔伤/附加物穿/附加魔穿/技能概率/暴击概率/攻击速度
- **次要词条**：物理攻击%/魔法攻击%/生命值/护盾/暴击穿透/双抗

  - **限流是真正干扰**：momozhen 对 Python urllib 连续请求限流（SSL 断开/返回空），浏览器 fetch 稳定；beach 轮询偶尔读不到可重跑
  - **beach_refresh 防二次刷新**：`beach(allow_refresh=False)` 避免 c=12 后 beach 又自动刷白耗箱子
  - **👀 浏览器视角空窗期待验证（2026-08-16 用户观察）**：浏览器强制刷新后**立即刷新网页**可能直接显示装备（无空窗感）——用户怀疑空窗期是脚本/限流视角的产物，下次有装备箱时实测：`c=12` → 浏览器立刻 reload 沙滩页，看是否直接出装备

**⚠️ Python urllib 限流问题（2026-08-16 确认 → ✅ 已迁移 requests.Session）**：
- **现象**：momozhen 对 Python urllib 连续请求限流严重——SSL 频繁断开（`UNEXPECTED_EOF_WHILE_READING`）、响应返回空（0 字节）、偶发 HTTP 错误；**浏览器 fetch 稳定不受影响**
- **根源**：urllib 每次 `urlopen` 都新建 TCP 连接 + TLS 握手，无连接池无 keep-alive，高频请求易触发服务器限流/DDoS 防护；且 `Content-Length`/头顺序等细节与真实浏览器有差异
- **✅ 已迁移（2026-08-16 深夜）**：`ggz_daily.py` 的 `request()` 改用 **requests.Session**（连接池 + keep-alive 复用 + 指数退避重试 `2^n + jitter`）。迁移后 stat/beach/gem 全流程**零重试**（旧 urllib 版 stat 都常 SSL 断开重试 1-2 次）。`requests` 依赖需 `pip install requests`（2.34.2 实测）
- **剩余规避手段（如需进一步优化）**：
  1. **降低请求频率**：批量操作（如 beach 逐件拾取、c=27 宝石连提）分批发、每发间隔 ≥2s（记忆 08-13 深夜：c=27 连发第 4 个起超时失败）
  2. **浏览器兜底**：脚本频繁失败时改用浏览器 MCP 操作（fyg 接口 fetch 直调），日常大数据量操作优先浏览器

```
    → 确认狗牌 ≥3（f=12；**狗牌=入场资格，翻牌不消耗狗牌**，2026-08-10 确认）
    → 读取 f=10（翻牌区 + 透视）
    → 若含透视 `是"幸运/稀有/史诗/传说"` → 按透视精准翻 3 同色
    → 若无透视 → 策略翻牌（参考 slack）：
        循环 c=8&id=1..12 翻牌（每张每天 1 次，最多 12 次/天）
        每翻一张刷新 f=10 看结果（按钮文本=品质）
        出现某色 ≥2 → 追该色保底
        出现传说 ≥2 → 无脑翻
        否则从左到右翻
    → 同色 3 张 → 结算获得对应品质奖励（**每日仅结算 1 次**，结算后剩余牌作废）→ 每日翻牌完成

[7] 额外奖励（可选，消耗药水）
    → c=13&id=1：消耗 1 药水，再领一次翻牌奖励
    → c=13&id=2：消耗 2 药水，重置今日狗牌+翻牌（重新打狗牌再翻）

[8] 收尾
    → 密钥续期：POST fyg_llpw_c.php iu=2（若用密钥登录）
    → 记录日志（出击数/狗牌/翻牌结果/工坊收益）
```

### 脚本内部逻辑（实测验证）
